# PA-Container 2.0: Agentic Software Factory Architecture & Implementation Plan

* **Status:** Architecture Specification & Detailed Engineering Design (RFC)
* **Target Repository:** `https://github.com/mikkovihonen/pa-container`
* **Core Subsystems Affected:** `pa` CLI (`crates/pa-cli`), `crates/pa-protocol`, `crates/pa-sandbox`, `crates/pa-agentd`, `pa_packages`, `coding-agent`, `coding-agent-proxy`
* **Target Environments:** macOS Desktop (Apple Silicon), Linux Desktop, Linux Server / Cloud Platforms

---

## 1. Executive Summary & Vision

`pa-container` began as a rootless Podman-based sandbox written in Python (`pa_core`) designed to launch an autonomous coding agent (`pi`, `opencode`, `antigravity`, or `claude`) inside a developer's local project directory (`cd /path/to/project && pa run`). By bind-mounting the host directory into a Fedora-based container attached to an `--internal` Podman network, `pa-container` guarantees that all HTTP, HTTPS, and DNS traffic traverses `coding-agent-proxy` (`mitmproxy`), enforcing hostname allowlists, placeholder token replacement, and complete flow export auditing.

The next evolutionary leap for `pa-container` is to transform from a **single-directory container wrapper** into a composable, portable **Agentic Software Factory** powered by a **Hybrid Rust Orchestration & Sandboxing Engine**:

1. **Rapid Capability Prototyping on Desktop:** Developers can rapidly experiment on their desktop (macOS or Linux) with different combinations of **Capability Packs (`pa_packages`)**—such as media generation and processing packages (`feat: media acps`), headless browser/desktop automation (`agent-desktop`), GPU-accelerated ML/server toolchains, and mobile development toolchains (iOS & Android)—to discover the exact capability set their software factory needs.
2. **Zero-Rewrite Cloud Promotion:** Once the optimal combination of agents and capability packages is validated on the desktop, the exact same declarative factory blueprint (`factory.toml`) can be deployed to a Linux server or cloud platform without re-architecting the workflow.
3. **Systems-Grade Rust Orchestration & Zero-Dependency Guest Daemons:** By rewriting the host orchestrator (`pa-cli`) and in-VM guest control/sandbox daemon (`pa-agentd`) as a static Rust workspace while preserving `coding-agent-proxy` on `mitmproxy`, the platform achieves $< 5\text{ ms}$ CLI startup, single-binary VM agent injection (requiring zero Python/`uv` bootstrap inside guest VMs), native Linux Landlock and macOS Seatbelt syscall enforcement without external C wrappers, and `zeroize`-backed secret handling in host memory.
4. **Uncompromised Network Introspection & Security:** Every network packet generated by any agent, capability package, build tool, GPU workload, or mobile simulator/emulator continues to be routed through an external `coding-agent-proxy` instance with per-agent identity attribution, while keeping the `mitmweb` inspection UI strictly bound to `127.0.0.1` and never exposed via public or overlay tunnels.

## 2. Assessment of the Current `pa-container` (v0.7.x) Architecture

### 2.1. Current Subsystem Inventory

Following the recent repository restructuring (`src/` $\rightarrow$ `pa_core/`, `packages/` $\rightarrow$ `pa_packages/`) and feature additions (`feat: media acps`, `t3-code`, multi-agent synthesis), the v0.7.x project consists of:

* **`pa` & `pa_core/` (92.2% Python, 6.2% Shell):** Python orchestration engine managing workspace initialization (`pa init`), image and toolchain building (`pa build`, `pa build --llama`), container lifecycle (`pa run`, `pa clean`), log inspection (`pa logs`), virtual desktop endpoints (`pa desktop`), and proxy queries (`pa proxy`). Includes reference-counted lifecycle management for shared host services.
* **`coding-agent-proxy/`:** Containerized `mitmproxy` (`mitmweb` / `mitmdump`) running custom Python addons:
    * **Allowlist Addon:** Filters egress HTTP/HTTPS requests and DNS queries (`:53`) by hostname/wildcard rules.
    * **Token Replacer Addon:** Substitutes placeholder credentials inside the agent environment with real secrets stored in the host `keyring` at the proxy boundary, preventing credential exfiltration by prompt-injected agents.
    * **Flow Export Addon:** Records full request/response streams to per-project `.mitm` audit files.
    * **Localhost-Only `mitmweb` UI:** Protected by `ADMIN_PASSWORD` (stored via `keyring`) and bound strictly to `127.0.0.1` for local developer auditing.
* **`coding-agent/`:** Fedora-based runtime image housing the core system environment, optional headless display stacks (**Wayland** via `labwc` + `wayvnc` + `noVNC`, or **X11** via `Xvfb` + `openbox` + `x11vnc`), `agent-desktop` UI automation CLI with **Chrome for Testing**, and **T3 Code** web UI integration (which optionally supports remote access via Tailscale and Cloudflare tunnels).
* **`pa_packages/` (Agent Capability Packages / ACPs):** Modular capability packages that bundle on-demand toolchains, CLI wrapper utilities, agent skills (`.pi/skills` synthesized across supported agents), and proxy/token configurations—such as the **Media ACPs**—into the agent environment alongside pluggable agent drivers (`pi`, `opencode`, `antigravity`, `claude`).

### 2.2. Terminology Evolution: Retiring "ACP" in Favor of "Capability Packs" (`capabilities`)

In `pa-container`, **ACP** was introduced as an abbreviation for **Agent Capability Packages** (housed in `pa_packages/`). As part of this architecture plan, the acronym **ACP** is phased out in favor of **Capability Packs** (configured as `capabilities` in TOML/CLI and implemented inside `pa_packages/`) for three reasons:

1. **Ecosystem Acronym Collision:** In the coding-agent ecosystem (including OpenCode, Pi, Zed, and JetBrains), **ACP** is the standard acronym for the *Agent Client Protocol* / *Agent Communication Protocol* (alongside *MCP* for Model Context Protocol). Using "ACP" for *Agent Capability Packages* creates ambiguity in documentation and agent logs.
2. **Direct Alignment with `pa_packages`:** Calling each modular unit in `pa_packages/` a **Capability Pack** (or simply a **Capability**) directly connects the user's workflow (*"selecting what capabilities a software factory has"*) with the repository layout (`pa_packages/`).
3. **Backward Compatibility:** During the transition, `pa-cli` will continue to accept `acps` in configuration files and CLI flags (`--acps`) as a deprecated alias for `capabilities` (`--capabilities`).

### 2.3. Architectural Bottlenecks Blocking the "Software Factory" Goal

1. **The Apple Silicon Hypervisor Barrier (GPU & Mobile Capabilities on macOS):**
   On macOS, Podman runs Linux containers inside a Linux virtual machine (`podman machine` over `Virtualization.framework`). Apple's hypervisor does **not** expose Metal, the Apple Neural Engine (ANE), PyTorch `mps`, or Apple MLX to Linux guest VMs. While `pa-container` works around this for text inference by running `llama-server` directly on the macOS host, Capability Packs inside the Fedora container cannot run native Apple GPU compute workloads (e.g., local GPU media generation/processing or PyTorch `mps` servers), nor can they build or test iOS applications (`xcodebuild` and `iOS Simulator` require a macOS kernel and Aqua `WindowServer`).
2. **Host Bind-Mount Coupling (`cd /project && pa run`):**
   Mounting a host working directory directly into the container ties the execution model to the developer's laptop filesystem:
    * On macOS, `virtiofs` bind-mounts suffer severe I/O degradation during heavy dependency builds (`node_modules`, `.venv`, Rust `target/`) and require complex `keep-id` UID/GID mapping.
    * It conflates the **Factory Blueprint** (agents, Capability Packs, proxy policies) with the **Target Codebase**.
    * Cloud environments do not have a developer's local directory to bind-mount; cloud factories ingest tasks via Git repositories and webhooks.
    * Multiple agents operating concurrently on a single bind-mounted directory collide on file locks, build artifacts, and Git index states.
3. **Per-Workspace Container & Image Layer Duplication:**
   Staging different combinations of `pa_packages` into per-workspace container images and running separate container pairs (`coding-agent` + `coding-agent-proxy`) per agent duplicates memory and disk overhead.
4. **Python Orchestration & Guest Runtime Dependencies:**
   Running an in-VM orchestration daemon, Landlock/Seatbelt sandboxing, and concurrent SSH/log/tunnel multiplexers in Python requires bootstrapping a matching Python interpreter and `uv` environment inside every guest VM (macOS Tart and Linux KVM) and maintaining separate C helper binaries for kernel syscalls like Landlock (`landlock_restrict_self`).

### 2.4. Why a Hybrid Rust Architecture (`pa-cli` + `pa-agentd` in Rust, `mitmproxy` in Python)

| Architectural Concern | Python Orchestration (`pa_core`) | Hybrid Rust Workspace (`pa-cli` + `pa-agentd`) | Benefit of Hybrid Rust |
| :--- | :--- | :--- | :--- |
| **Guest VM Daemon Injection** | Requires Python $3.12+$ & `uv` pre-installed in every VM image | Single $4\text{ MB}$ static `musl` (Linux) or Mach-O (macOS) binary | Can be `scp`/virtio-copied into any vanilla Tart or Incus VM image at boot |
| **Kernel Sandboxing (Landlock / UID / `prctl`)** | Requires external `gcc` compilation of `landlock_helper.c` | Native Rust `landlock` & `nix` crates inside `Command::pre_exec` | Memory-safe syscall enforcement in the same binary; zero external C build step |
| **macOS `iOS Simulator` Bridge (`pa-ios-runnerd`)** | Separate Python LaunchAgent script inside Aqua session | Subcommand (`pa-agentd ios-runnerd`) of the same Mach-O binary | Unified binary manages both POSIX sandboxes and Aqua Simulator sockets |
| **Secret Memory Hygiene** | Python strings are immutable & garbage-collected unpredictably | `keyring` + `zeroize::Zeroizing<String>` wipes secrets on scope drop | Host API keys exist in process RAM for $< 1\text{ ms}$ during policy generation |
| **Async Multiplexing** | `subprocess` / `asyncio` threads for SSH RPC, logs, and refcounts | `tokio` async tasks with structured cancellation & `flock` | High-concurrency orchestration across 10+ parallel agents |
| **CLI Startup Latency** | $120\text{--}300\text{ ms}$ (`uv run` + Python import graph) | $2\text{--}8\text{ ms}$ native binary | Instantaneous `pa status`, `pa proxy`, `pa logs`, and `pa review` |
| **Traffic Introspection (`coding-agent-proxy`)** | `mitmproxy` + `mitmweb` + Python addons | **Retained on `mitmproxy` + `mitmweb`** | Preserves battle-tested TLS/DNS interception and `mitmweb` UI |

## 3. Target Architecture: 3-Tier Factory VM + Multi-User OS Sandboxes + External Proxy

To solve all bottlenecks while preserving every existing strength of `pa-container`, the target architecture replaces the single-container bind-mount model with a **Three-Tier Isolation Model**:

1. **Tier 1 — External `coding-agent-proxy` & Rust Host Control Plane (`pa-cli`):** The `mitmproxy` security boundary remains strictly **outside** the Factory VM. Even a total kernel or root compromise inside the Factory VM cannot access `keyring` secrets, bypass the allowlist, or alter exported `.mitm` audit logs.
2. **Tier 2 — The Factory VM ("The Factory Floor"):** A hardware-virtualized guest OS supervised by the static `pa-agentd` Rust binary, providing kernel isolation and native GPU access:
    * **On macOS Desktop:** A macOS Guest VM powered by **Tart** (`Virtualization.framework`), providing paravirtualized Metal GPU ($\approx 92\%$ native speed), MLX, Xcode, and iOS Simulator.
    * **On Linux Desktop & Server/Cloud:** A Linux Guest VM powered by **Incus VM** or **Cloud Hypervisor** (or a native Cloud VM instance in production) with KVM isolation and direct VFIO / Virtio-GPU (`/dev/dri`, `/dev/nvidia*`) passthrough.
3. **Tier 3 — Multi-User POSIX Workstations + OS Process Sandboxes ("The Workbenches"):** Inside the Factory VM, `pa-agentd` spawns each coding agent as a dedicated, unprivileged POSIX user (`agent1` with $\text{UID } 2001$, `agent2` with $\text{UID } 2002$, etc.) wrapped in an OS-native mandatory access control sandbox (**Seatbelt `sandbox-exec`** on macOS; **Bubblewrap `bwrap` + native Rust Landlock** on Linux) over an instant Copy-on-Write (CoW) Git clone, with its selected **Capability Packs (`pa_packages`)** mounted read-only.

| Layer | macOS Desktop (Apple Silicon) | Linux Desktop & Cloud Server | Architectural Purpose |
| :--- | :--- | :--- | :--- |

## 4. Network Architecture & Multi-Agent `coding-agent-proxy` (Option A)

Keeping `coding-agent-proxy` outside the Factory VM creates a fundamental routing challenge: standard TCP/IP packets leaving a VM do not carry the guest OS user ID ($\text{UID}$) that originated them. **Option A** solves this cleanly and deterministically using **UID-to-Port Mapping**:

* `coding-agent-proxy` listens on a dedicated port per active agent slot ($8081 \rightarrow \text{agent1}$, $8082 \rightarrow \text{agent2}$, ..., $8080 + N \rightarrow \text{agent}N$).
* The guest OS kernel firewall (`pf` or `nftables`) matches outbound packets by the originating socket's kernel $\text{UID}$ and permits/redirects traffic **only** to that specific user's assigned port on the external proxy.

### 4.1. Three-Layer Defense-in-Depth Network Lockdown

#### Layer 1: Hypervisor-Level Egress Filter (Outside the VM)

* **On macOS (Tart + Softnet):**
  `pa-cli` launches the Tart VM connected to Softnet restricted strictly to the host IP of `coding-agent-proxy`:
  ```bash
  tart run \
    --net-softnet \
    --net-softnet-allow="${PROXY_HOST_IP}/32" \
    --no-clipboard \
    --no-audio \
    pa-factory-macos:latest
  ```
  Even if an attacker compromises root inside the macOS guest VM and flushes `/etc/pf.conf`, the hypervisor drops every packet sent to any IP address other than `${PROXY_HOST_IP}`.
* **On Linux (Incus / KVM Bridge + Host `nftables`):**
  The Factory VM attaches to an internal bridge (`pa-br0`) with no default IP forwarding enabled on the host. Host `nftables` allows traffic from `pa-br0` solely to the `coding-agent-proxy` container/process IP on ports $5353$ and $8080\text{--}8099$.

#### Layer 2: Guest OS Kernel Firewall (UID-to-Port Enforcement)

* **macOS Guest VM (`/etc/pf.conf`):**
  Compiled and loaded atomically by `pa-agentd` at boot, with IPv6 disabled (`networksetup -setv6off Ethernet`):
  ```pf
  # Macros injected by pa-agentd (crates/pa-sandbox)
  proxy_ip = "192.168.64.1"
  dns_port = "5353"

  set block-policy return
  set skip on lo0

  # Default deny all outbound and inbound traffic
  block in all
  block out all

  # Allow inbound SSH/control only from the host gateway to pa-agentd
  pass in quick proto tcp from $proxy_ip to any port 2222 keep state

  # Allow DNS queries ONLY to coding-agent-proxy DNS listener
  pass out quick proto { tcp, udp } from any to $proxy_ip port $dns_port user { _pa_daemon, agent1, agent2, agent3, agent4 } keep state

  # Strict UID-to-Proxy-Port lockdown per agent user
  pass out quick proto tcp from any to $proxy_ip port 8080 user _pa_daemon keep state
  pass out quick proto tcp from any to $proxy_ip port 8081 user agent1 keep state
  pass out quick proto tcp from any to $proxy_ip port 8082 user agent2 keep state
  pass out quick proto tcp from any to $proxy_ip port 8083 user agent3 keep state
  pass out quick proto tcp from any to $proxy_ip port 8084 user agent4 keep state
  ```

* **Linux Guest VM (`/etc/nftables.conf`):**
  On Linux, `nftables` provides both strict port filtering (`8081..8084` for explicit `HTTP_PROXY` clients) **and** transparent `DNAT` redirection (`8091..8094` in `--mode transparent`) for binaries that ignore `HTTP_PROXY` environment variables:
  ```nft
  flush ruleset

  define PROXY_IP = 10.240.0.1
  define DNS_PORT = 5353

  table ip pa_factory {
      chain nat_output {
          type nat hook output priority -100; policy accept;

          # Do not redirect traffic targeting localhost or already targeting the proxy IP
          ip daddr 127.0.0.0/8 return
          ip daddr $PROXY_IP return

          # Redirect all direct DNS traffic from agents to coding-agent-proxy DNS
          meta skuid >= 2001 udp dport 53 dnat to $PROXY_IP:$DNS_PORT
          meta skuid >= 2001 tcp dport 53 dnat to $PROXY_IP:$DNS_PORT

          # Redirect direct HTTP/HTTPS calls (tools ignoring HTTP_PROXY) to transparent proxy ports
          meta skuid "agent1" tcp dport { 80, 443 } dnat to $PROXY_IP:8091
          meta skuid "agent2" tcp dport { 80, 443 } dnat to $PROXY_IP:8092
          meta skuid "agent3" tcp dport { 80, 443 } dnat to $PROXY_IP:8093
      }

      chain filter_output {
          type filter hook output priority 0; policy drop;

          oifname "lo" accept
          ct state established,related accept

          # Allow DNS to proxy
          meta skuid { "_pa_daemon", "agent1", "agent2", "agent3" } ip daddr $PROXY_IP udp dport $DNS_PORT accept
          meta skuid { "_pa_daemon", "agent1", "agent2", "agent3" } ip daddr $PROXY_IP tcp dport $DNS_PORT accept

          # Allow each agent UID ONLY to its own regular (808N) and transparent (809N) proxy ports
          meta skuid "_pa_daemon" ip daddr $PROXY_IP tcp dport 8080 accept
          meta skuid "agent1" ip daddr $PROXY_IP tcp dport { 8081, 8091 } accept
          meta skuid "agent2" ip daddr $PROXY_IP tcp dport { 8082, 8092 } accept
          meta skuid "agent3" ip daddr $PROXY_IP tcp dport { 8083, 8093 } accept
      }
  }
  ```

#### Layer 3: Process Sandbox Network Enforcement (`crates/pa-sandbox`)

* Both the macOS Seatbelt profile and the Linux native Rust Landlock `pre_exec` hook restrict the agent process tree so that `connect()` syscalls are only permitted to `127.0.0.1:*` (for local dev servers/test runners) and `$PROXY_IP:$AGENT_PORT`.

### 4.2. Security Policy: `mitmweb` Must Never Be Exposed via Tailscale or Cloudflare Tunnels

A strict compile-time and runtime security invariant of `pa-container` is the separation between **collaborative agent UIs** and **privileged security/audit interfaces**:

* **`mitmweb` is Strictly Localhost-Only (`127.0.0.1`):**
  `mitmweb` provides live inspection of all HTTP/HTTPS payloads, ability to replay requests, and visibility into proxy operations. Therefore, `mitmweb` **must never** be advertised or exposed via Tailscale (`tailscale serve` / `funnel`) or Cloudflare tunnels (`cloudflared`), nor bound to `0.0.0.0` on external interfaces.
    * **On Desktop:** `mitmweb` binds strictly to `127.0.0.1:<web_port>` on the host and requires `ADMIN_PASSWORD` authentication.
    * **On Linux Server / Cloud:** `mitmweb` binds strictly to `127.0.0.1:<web_port>` on the remote host's loopback interface. Developers inspecting live traffic on a cloud factory use `pa proxy -o --ssh-tunnel`, which establishes an authenticated local SSH port-forward (`ssh -L 127.0.0.1:8080:127.0.0.1:<web_port>`) rather than exposing `mitmweb` to any tunnel or overlay network.
* **Remote Tunnels (Tailscale & Cloudflare) Are Restricted to T3 Code:**
  As documented in `docs/t3-code.md`, Tailscale and Cloudflare tunnel integrations in `pa-cli` accept only a `T3CodeEndpoint` newtype struct (never a `MitmwebEndpoint`), making accidental tunnel exposure of `mitmweb` a compile-time type error in Rust.

## 5. Capability Packs Architecture (`pa_packages`) & Inner OS Sandboxes

### 5.1. Aligning `capability.toml` with the Current Organization of `pa_packages`

In `pa-container` v0.7.x (including `feat: media acps` and the `pa_packages/` hierarchy), packages in `pa_packages/` are organized as self-contained units that combine **four elements**:

1. **Toolchain & Dependency Installation:** Containerfile layer snippets / Fedora `dnf` packages, Python `uv` tools/scripts, or Node packages staged during `pa build`.
2. **Executable CLI Helpers & Provider Scripts:** Python, Rust, or shell CLI entrypoints (such as the media generation/processing CLI wrappers in `feat: media acps` or `agent-desktop`) placed on the agent's `PATH`.
3. **Agent Skill Definitions (`SKILL.md`):** Structured markdown instructions and tool usage guides staged into `.pi/skills/<name>/SKILL.md` and synthesized/adapted for all supported agents (`pi`, `opencode`, `antigravity`, `claude`).
4. **Workspace Configuration & Proxy Wiring:** Default `allowlist` domains, `keyring` token placeholders for `token_replacer`, and environment variables synthesized by `pa-cli` when the package is enabled.

To support both the existing Podman container builder (`podman-legacy`) and the new multi-user Factory VM (`macos-tart`, `linux-incus`, `linux-cloud`) without duplicating package definitions, each directory under `pa_packages/` follows a unified layout backed by `capability.toml`:

## 6. Workspace Management: Replacing Bind-Mounts with Git Vault, CoW Clones & IDE Bridges

```
[Developer Host Repository]               [Factory VM: /var/pa-vault/repo.git]
 (macOS / Linux Desktop)   <--- git --->   (Owned by _pa_daemon, Bare Git Vault)
         |                                          |                    |
  pa review agent1                         CoW Clone (APFS/Btrfs)  CoW Clone (APFS/Btrfs)
  (git worktree add                                 v                    v
   .pa/review/agent1)                     [/home/agent1/workspace] [/home/agent2/workspace]
                                           Branch: pa/agent1/task   Branch: pa/agent2/task
```

1. **Ingestion (`pa run` or `pa task submit`):** `pa-cli` pushes the current host `HEAD` (plus uncommitted working tree changes captured via `git stash create --include-untracked` as a synthetic commit on `refs/pa/ingest/latest`) into `/var/pa-vault/<project>.git` inside the Factory VM.
2. **Millisecond Copy-on-Write Agent Clone:** `pa-agentd` clones `/var/pa-vault/checkouts/<project>-main` into `/home/agent1/workspace` via APFS `cp -c -R` (macOS) or Btrfs/XFS `cp --reflink=always -a` (Linux).
3. **Branch-Scoped Local Git Remote:** Pre-receive hooks inside `/var/pa-vault/<project>.git` verify peer credentials so `agent1` can fetch all branches but can **only** push to `refs/heads/pa/agent1/*`.
4. **Local IDE Code Review (`pa review <agent-id>`):** `pa-cli` fetches `refs/heads/pa/<agent-id>/*` from the Factory VM Vault into the host repository and executes `git worktree add .pa/review/<agent-id>` on the host for instant inspection in VS Code, Cursor, Xcode, or Android Studio.

### 8.2. Crate Design: `crates/pa-protocol/src/manifest.rs`

`pa-protocol` defines the strongly typed `serde` schemas for `capability.toml`, `factory.toml`, and the topological dependency resolver shared between `pa-cli` and `pa-agentd`.

```rust
use std::fs;
use std::path::{Path, PathBuf};
use anyhow::{bail, Context, Result};

    #[serde(default)]
    pub ro_binds: Vec<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityManifest {
    pub schema_version: String,
    pub capability: CapabilityHeader,
    pub staging: StagingSpec,
    #[serde(default)]
    pub env: HashMap<String, String>,
    pub skills: Option<SkillSpec>,
    #[serde(default)]
    pub proxy: ProxySpec,
    #[serde(default)]
    pub sandbox: SandboxEntitlementSpec,
    #[serde(skip)]
    pub package_dir: PathBuf,
}

pub struct CapabilityRegistry {
    by_name: HashMap<String, CapabilityManifest>,
    alias_map: HashMap<String, String>,
}

impl CapabilityRegistry {
    pub fn discover(packages_root: &Path) -> Result<Self> {
        let mut by_name = HashMap::new();
        let mut alias_map = HashMap::new();

        for sub in ["toolchains", "capabilities"] {
            let base = packages_root.join(sub);
            if !base.exists() {
                continue;
            }
            for entry in fs::read_dir(&base)? {
                let entry = entry?;
                let toml_path = entry.path().join("capability.toml");
                if !toml_path.is_file() {
                    continue;
                }
                let raw = fs::read_to_string(&toml_path)
                    .with_context(|| format!("Failed to read {}", toml_path.display()))?;
                let mut manifest: CapabilityManifest = toml::from_str(&raw)
                    .with_context(|| format!("Invalid capability.toml at {}", toml_path.display()))?;
                manifest.package_dir = entry.path();

                let name = manifest.capability.name.clone();
                for alias in &manifest.capability.aliases {
                    alias_map.insert(alias.clone(), name.clone());
                }
                by_name.insert(name, manifest);
            }
        }
        Ok(Self { by_name, alias_map })
    }

    pub fn resolve_name<'a>(&'a self, name_or_alias: &'a str) -> Result<&'a str> {
        if self.by_name.contains_key(name_or_alias) {
            return Ok(name_or_alias);
        }
        if let Some(canonical) = self.alias_map.get(name_or_alias) {
            return Ok(canonical.as_str());
        }
        bail!("Unknown capability pack or legacy ACP alias: '{name_or_alias}'")
    }

    pub fn resolve_dependency_closure(&self, requested: &[String]) -> Result<Vec<CapabilityManifest>> {
        #[derive(Clone, Copy, PartialEq, Eq)]
        enum VisitState { Temp, Perm }

        let mut state: HashMap<String, VisitState> = HashMap::new();
        let mut ordered = Vec::new();

        fn visit(
            reg: &CapabilityRegistry,
            raw: &str,
            state: &mut HashMap<String, VisitState>,
            ordered: &mut Vec<CapabilityManifest>,
        ) -> Result<()> {
            let canonical = reg.resolve_name(raw)?.to_string();
            match state.get(&canonical) {
                Some(VisitState::Perm) => return Ok(()),
                Some(VisitState::Temp) => bail!("Circular capability dependency involving '{canonical}'"),
                None => {}
            }
            state.insert(canonical.clone(), VisitState::Temp);
            let manifest = &reg.by_name[&canonical];
            for dep in &manifest.capability.requires {
                visit(reg, dep, state, ordered)?;
            }
            state.insert(canonical, VisitState::Perm);
            ordered.push(manifest.clone());
            Ok(())
        }

        for req in requested {
            visit(self, req, &mut state, &mut ordered)?;
        }
        Ok(ordered)
    }
}
```

### 8.3. Crate Design: `crates/pa-cli/src/composer.rs` (Zeroized Secrets & Placeholder Synthesis)

`composer.rs` fetches real credentials from the host OS `keyring`, wraps them in `zeroize::Zeroizing<String>` so they are scrubbed from memory immediately when dropped, derives opaque HMAC-SHA256 placeholders for the agent environment, and writes the `0600` policy file for `coding-agent-proxy`.

```rust
// crates/pa-cli/src/composer.rs

use sha2::Sha256;
use zeroize::Zeroizing;
use serde::Serialize;
use pa_protocol::manifest::{CapabilityManifest, GpuRequirement};

type HmacSha256 = Hmac<Sha256>;

#[derive(Clone, Serialize)]
pub struct ResolvedTokenBinding {
    pub env_var: String,
    pub placeholder: String,
    pub secret_value: Zeroizing<String>,
    pub allowed_hosts: Vec<String>,
}

#[derive(Debug, Clone, Serialize)]
pub struct ComposedAgentEnvironment {
    pub agent_id: String,
    pub user: String,
    pub uid: u32,
    pub driver: String,
    pub proxy_port: u16,
    pub transparent_proxy_port: u16,
    pub capabilities: Vec<String>,
    pub ro_binds: Vec<String>,
    pub path_entries: Vec<String>,

    pub allowed_hosts: Vec<String>,
    pub gpu_mode: GpuRequirement,
    pub display_required: bool,
}

pub fn derive_placeholder_token(session_nonce: &[u8], agent_id: &str, env_var: &str) -> String {
    let mut mac = HmacSha256::new_from_slice(session_nonce)
        .expect("HMAC accepts keys of any size");
    mac.update(agent_id.as_bytes());
    mac.update(b":");
    mac.update(env_var.as_bytes());
    let digest = mac.finalize().into_bytes();
    let hex_prefix: String = digest.iter().take(8).map(|b| format!("{b:02x}")).collect();
    format!("pa-tok-{agent_id}-{hex_prefix}")
}
```

#### Placeholder Token Formula & Host-Scoped Secret Protection

$$
\text{Placeholder}(\text{agent\_id}, \text{env\_var}) = \texttt{"pa-tok-"} \parallel \text{agent\_id} \parallel \texttt{"-"} \parallel \operatorname{HMAC-SHA256}_{[:16]}(\text{session\_nonce}, \text{agent\_id} \parallel \texttt{":"} \parallel \text{env\_var})
$$

* The agent process inside the VM receives `OPENAI_API_KEY=pa-tok-agent1-9f8a7b6c5d4e3f2a` (the real secret never enters the VM).
* `coding-agent-proxy` on the host receives the mapping `pa-tok-agent1-9f8a7b6c5d4e3f2a` $\rightarrow$ `(real_secret, allowed_hosts=["api.openai.com"])` strictly on port `8081` / `8091`.

### 8.4. Module Design: `coding-agent-proxy/addons/pipeline.py` (Retained on `mitmproxy`)

`coding-agent-proxy` continues to use `mitmproxy` (`mitmweb` / `mitmdump`) and dynamically hot-reloads `/run/pa-proxy/proxy-policy.json` generated by `pa-cli`:

```python
# coding-agent-proxy/addons/pipeline.py
from __future__ import annotations
import fnmatch
import json
from pathlib import Path
from mitmproxy import ctx, dns, http, io

class MultiAgentProxyPipeline:
    """Unified mitmproxy addon enforcing per-port agent identity, allowlist,
    host-scoped token replacement, and per-agent .mitm flow export."""

    def __init__(self) -> None:
        self.policy_path: Path | None = None
        self.policy_mtime: float = 0.0
        self.port_policies: dict[int, dict] = {}
        self.dns_allowed_hosts: set[str] = set()
        self.flow_writers: dict[str, io.FlowWriter] = {}

    def load(self, loader) -> None:
        loader.add_option(
            name="pa_policy_file",
            typespec=str,
            default="/run/pa-proxy/proxy-policy.json",
            help="Path to multi-agent proxy policy JSON file written by Rust pa-cli",
        )

    def configure(self, updated: set[str]) -> None:
        if "pa_policy_file" in updated:
            self.policy_path = Path(ctx.options.pa_policy_file)
            self._reload_if_needed(force=True)

    def _reload_if_needed(self, force: bool = False) -> None:
        if not self.policy_path or not self.policy_path.exists():
            return
        mtime = self.policy_path.stat().st_mtime
        if not force and mtime <= self.policy_mtime:
            return
        data = json.loads(self.policy_path.read_text(encoding="utf-8"))
        self.port_policies.clear()
        self.dns_allowed_hosts.clear()
        for agent in data.get("agents", []):
            for port_key in ("proxy_port", "transparent_proxy_port"):
                port = agent.get(port_key)
                if port:
                    self.port_policies[int(port)] = agent
            for host_pattern in agent.get("allowed_hosts", []):
                self.dns_allowed_hosts.add(host_pattern.lower())
        self.policy_mtime = mtime

    def _host_matches(self, host: str, patterns: list[str] | set[str]) -> bool:
        host_l = host.lower().rstrip(".")
        for pat in patterns:
            pat_l = pat.lower().rstrip(".")
            if host_l == pat_l or fnmatch.fnmatch(host_l, pat_l):
                return True
            if pat_l.startswith("*.") and host_l == pat_l[2:]:
                return True
        return False

    def dns_request(self, flow: dns.DNSFlow) -> None:
        self._reload_if_needed()
        question = flow.request.question
        if not question:
            return
        if not self._host_matches(question.name, self.dns_allowed_hosts):
            flow.response = flow.request.fail(dns.response_codes.REFUSED)

    def request(self, flow: http.HTTPFlow) -> None:
        self._reload_if_needed()
        _, local_port = flow.client_conn.sockname[:2]
        policy = self.port_policies.get(local_port)
        if policy is None:
            flow.response = http.Response.make(
                403, b"PA-Proxy Error: Unregistered agent proxy port.\n"
            )
            return

        agent_id = policy["agent_id"]
        flow.metadata["pa_agent_id"] = agent_id
        flow.metadata["pa_capabilities"] = policy.get("capabilities", [])

        target_host = flow.request.pretty_host
        if not self._host_matches(target_host, policy.get("allowed_hosts", [])):
            flow.response = http.Response.make(
                403,
                f"PA-Proxy Allowlist Denied: Agent '{agent_id}' is not permitted to access '{target_host}'.\n".encode(),
            )
            return

        for rule in policy.get("token_rules", []):
            placeholder = rule["placeholder"]
            secret = rule["secret_value"]
            if self._host_matches(target_host, rule["allowed_hosts"]):
                for k, v in list(flow.request.headers.items()):
                    if placeholder in v:
                        flow.request.headers[k] = v.replace(placeholder, secret)
                if placeholder in flow.request.path:
                    flow.request.path = flow.request.path.replace(placeholder, secret)
                if flow.request.raw_content and placeholder.encode() in flow.request.raw_content:
                    flow.request.raw_content = flow.request.raw_content.replace(
                        placeholder.encode(), secret.encode()
                    )
            else:
                for k, v in list(flow.request.headers.items()):
                    if placeholder in v:
                        flow.response = http.Response.make(
                            403,
                            f"PA-Proxy Token Security Violation: Token for {rule['env_var']} cannot be sent to {target_host}.\n".encode(),
                        )
                        return

    def response(self, flow: http.HTTPFlow) -> None:
        agent_id = flow.metadata.get("pa_agent_id")
        if not agent_id:
            return
        _, local_port = flow.client_conn.sockname[:2]
        policy = self.port_policies.get(local_port)
        if not policy:
            return
        log_path = policy.get("flow_log_path")
        if log_path:
            if agent_id not in self.flow_writers:
                Path(log_path).parent.mkdir(parents=True, exist_ok=True)
                f = open(log_path, "ab")
                self.flow_writers[agent_id] = io.FlowWriter(f)
            self.flow_writers[agent_id].add(flow)

addons = [MultiAgentProxyPipeline()]
```

### 9.2. Crate Design: `crates/pa-sandbox/src/linux_landlock.rs` (Native Rust Landlock ABI v4+ Enforcer)

Using the official `landlock` crate and `std::os::unix::process::CommandExt::pre_exec`, `pa-sandbox` applies `PR_SET_NO_NEW_PRIVS` and Landlock TCP connect/bind port filters directly inside the child process right before `execvp`, completely eliminating `landlock_helper.c`:

```rust
// crates/pa-sandbox/src/linux_landlock.rs
#[cfg(target_os = "linux")]
use landlock::{
    ABI, Access, AccessNet, NetPort, Ruleset, RulesetAttr, RulesetCreatedAttr, RulesetStatus,
};
use anyhow::{Context, Result};
use std::os::unix::process::CommandExt;
use std::process::Command;

#[cfg(target_os = "linux")]
pub fn apply_landlock_tcp_lockdown(proxy_port: u16, transparent_port: u16, dns_port: u16) -> Result<()> {
    let abi = ABI::V4;
    let mut ruleset = Ruleset::default()
        .handle_access(AccessNet::ConnectTcp | AccessNet::BindTcp)?
        .create()?;

    // Allow outbound TCP to agent's dedicated regular & transparent proxy ports, DNS, and Vault Git
    for port in [proxy_port, transparent_port, dns_port, 9418] {
        ruleset = ruleset.add_rule(NetPort::new(port, AccessNet::ConnectTcp))?;
    }

    // Allow local dev servers & test runners on loopback ports 3000..=9000 (restricted to `lo` by nftables)
    for port in 3000..=9000 {
        ruleset = ruleset.add_rule(
            NetPort::new(port, AccessNet::ConnectTcp | AccessNet::BindTcp),
        )?;
    }

    let status = ruleset.restrict_self().context("Failed to apply Landlock TCP ruleset")?;
    if matches!(status.ruleset, RulesetStatus::NotEnforced) {
        // Kernel < 6.7 fallback: nftables meta skuid rules still strictly enforce UID-to-port routing
    }
    Ok(())
}

pub fn build_linux_bwrap_command(

    for pack_path in ro_binds {

    }

        }
    }

    cmd.arg("--");

                nix::unistd::Uid::from_raw(uid),
            ).map_err(|e| std::io::Error::from_raw_os_error(e as i32))?;

            apply_landlock_tcp_lockdown(proxy_port, transparent_port, dns_port)
                .map_err(|e| std::io::Error::new(std::io::ErrorKind::PermissionDenied, e.to_string()))?;
            Ok(())
        });
    }
```

### 9.3. Crate Design: `crates/pa-agentd/src/git_vault.rs` (CoW Workspace Cloner & Dirty Tree Ingest)

```rust
// crates/pa-agentd/src/git_vault.rs
use std::fs;
use std::path::Path;
use std::process::Command;
use anyhow::{bail, Context, Result};

pub fn clone_workspace_cow(reference_checkout: &Path, target_workspace: &Path, uid: u32, gid: u32) -> Result<()> {
    if target_workspace.exists() {
        fs::remove_dir_all(target_workspace)
            .with_context(|| format!("Failed to clean existing workspace {}", target_workspace.display()))?;
    }
    if let Some(parent) = target_workspace.parent() {
        fs::create_dir_all(parent)?;
    }

    #[cfg(target_os = "macos")]
    {
        // APFS instant Copy-on-Write clone
        let status = Command::new("cp")
            .args(["-c", "-R"])
            .arg(reference_checkout)
            .arg(target_workspace)
            .status()?;
        if !status.success() {
            let fallback = Command::new("cp")
                .arg("-R")
                .arg(reference_checkout)
                .arg(target_workspace)
                .status()?;
            if !fallback.success() {
                bail!("Failed to clone workspace on macOS");
            }
        }
    }

    #[cfg(target_os = "linux")]
    {
        // Btrfs / XFS / ZFS reflink Copy-on-Write clone
        let status = Command::new("cp")
            .args(["--reflink=always", "-a"])
            .arg(reference_checkout)
            .arg(target_workspace)
            .status()?;
        if !status.success() {
            let fallback = Command::new("cp")
                .arg("-a")
                .arg(reference_checkout)
                .arg(target_workspace)
                .status()?;
            if !fallback.success() {
                bail!("Failed to clone workspace on Linux");
            }
        }
    }

    let status = Command::new("chown")
        .args(["-R", &format!("{uid}:{gid}")])
        .arg(target_workspace)
        .status()?;
    if !status.success() {
        bail!("chown failed on {}", target_workspace.display());
    }
    Ok(())
}
```

## 10. Detailed Engineering Design: Phase 3 (macOS Tart VM, Seatbelt Compiler & `pa-agentd ios-runnerd`)

**Phase 3 Scope:** `TartMacOSBackend` (`crates/pa-cli/src/backends/tart_macos.rs`) with Softnet egress lockdown, macOS `dscl` user provisioning, dynamic Seatbelt `.sb` compiler (`crates/pa-sandbox/src/macos_seatbelt.rs`) with Apple Silicon Metal/ANE IOKit entitlements, and the `pa-agentd ios-runnerd` subcommand (`crates/pa-agentd/src/ios_runner.rs`) + `pa-ios` CLI.

**Phase 3 Exit Criteria:**
1. On Apple Silicon macOS, `pa factory up` clones and boots a macOS Tart VM locked with `--net-softnet --net-softnet-allow="${PROXY_HOST_IP}/32"` and injects the static Mach-O `pa-agentd` binary.
2. Multiple agents run concurrently as isolated macOS POSIX users (`agent1..N`) inside dynamically synthesized Seatbelt (`sandbox-exec`) profiles with full paravirtualized Metal (`torch.device("mps")`, Apple MLX, `ggml-metal`) acceleration.
3. An agent equipped with the `mobile-ios` Capability Pack can compile an iOS app with `xcodebuild`, install and launch it in a dedicated `iOS Simulator` via `pa-ios`, inspect UI elements/screenshots, and have all Simulator HTTPS traffic intercepted and logged in that agent's `.mitm` file.

```rust
// crates/pa-agentd/src/ios_runner.rs
use std::path::Path;
use std::process::Command;
use anyhow::{bail, Context, Result};

pub struct IosSimulatorManager {
    ca_cert_path: String,
    proxy_ip: String,
}

impl IosSimulatorManager {
    pub fn ensure_agent_simulator(&self, agent_id: &str, device_type: &str) -> Result<String> {
        let sim_name = format!("pa-sim-{agent_id}");
        let udid = match self.find_sim_udid(&sim_name)? {
            Some(id) => id,
            None => {
                let out = Command::new("xcrun")
                    .args(["simctl", "create", &sim_name, device_type])
                    .output()
                    .context("Failed to execute xcrun simctl create")?;
                if !out.status.success() {
                    bail!("simctl create failed: {}", String::from_utf8_lossy(&out.stderr));
                }
                String::from_utf8(out.stdout)?.trim().to_string()
            }
        };

        // Boot simulator in headless Aqua session and wait until ready
        let status = Command::new("xcrun")
            .args(["simctl", "bootstatus", &udid, "-b"])
            .status()?;
        if !status.success() {
            bail!("simctl bootstatus failed for UDID {udid}");
        }

        // Inject external coding-agent-proxy Root CA into Simulator trusted store
        if Path::new(&self.ca_cert_path).exists() {
            let cert_status = Command::new("xcrun")
                .args(["simctl", "keychain", &udid, "add-root-cert", &self.ca_cert_path])
                .status()?;
            if !cert_status.success() {
                bail!("Failed to install mitmproxy CA into simulator {udid}");
            }
        }
        Ok(udid)
    }

    pub fn launch_app_with_agent_proxy(
        &self,
        udid: &str,
        bundle_id: &str,
        agent_proxy_port: u16,
        args: &[String],
    ) -> Result<()> {
        let proxy_url = format!("http://{}:{}", self.proxy_ip, agent_proxy_port);
        let mut cmd = Command::new("xcrun");
        cmd.env("SIMCTL_CHILD_HTTP_PROXY", &proxy_url)
            .env("SIMCTL_CHILD_HTTPS_PROXY", &proxy_url)
            .env("SIMCTL_CHILD_ALL_PROXY", &proxy_url)
            .args(["simctl", "launch", udid, bundle_id])
            .args(args);

        let status = cmd.status()?;
        if !status.success() {
            bail!("Failed to launch {bundle_id} on simulator {udid}");
        }
        Ok(())
    }

    fn find_sim_udid(&self, _sim_name: &str) -> Result<Option<String>> {
        // Parses `xcrun simctl list devices -j` via serde_json
        Ok(None)
    }
```
